# Consistent Writing · 一致写作

[English](./README.en.md) · [MIT License](./LICENSE)

**改好这一段，也让它和整篇文章对得上。**

你让 AI 改第三段，它换了一个更顺口的词。到了第五段，同一个概念又有了新名字。再压缩一次，支撑观点的理由也被一起删掉。每段读起来都像那么回事，整篇却慢慢偏离了最初的意思。

Consistent Writing 是一组面向中文和英文写作的 Agent Skills，重点处理**局部修改与全文的衔接，以及概念和术语的一致性**。改一段、续一节、换一种表达时，结合已有上下文，核对改稿是否延续原来的意思、名称和定义。在这个基础上，再整理段落、减少防御性写作和套路化表达，也支持从零起草全文。

[中文技能](./clear-chinese-writing/SKILL.md) · [English skill](./clear-english-writing/SKILL.md) · [开始使用](#开始使用)

## 写着写着，哪里变了？

| 你遇到的问题 | 技能要求 AI 怎么处理 |
| --- | --- |
| 只改了一段，全文的重点却跟着变了 | 先从已有上下文确认主旨和该段的作用，再做局部修改 |
| 同一个概念，每段换一个叫法 | 沿用已经确认的名称和定义，核对近义词是否真的指同一件事 |
| 突然冒出一个听起来很厉害的新名词 | 优先写出具体含义，确实需要命名时解释范围与适用条件 |
| 说“精简一点”，重要理由和实际收益没了 | 按信息的作用决定取舍，检查关键理由、证据和条件是否仍在 |
| 文章没有明显错误，但处处像套模板 | 检查碎片化分段、反复辩解、机械排比和无依据的拔高 |

## 先把意思写对，再把话写好

### 核心要求

**主旨与上下文。** 全文起草时，先理清各部分共同要说明什么。逐段修改时，结合前文和相关段落判断当前修改的作用。你明确改变方向后，技能要求识别哪些旧表述也需要调整，并按本次修改范围处理。

**概念与术语。** 同一概念保持名称稳定，相近概念保留必要区别。新术语需要让读者知道它指什么、适用于哪里。中文和英文各有一份独立技能，分别处理对应语言中的名称、指代和表达习惯。

### 配套写作规则

- **段落组织**——合并围绕同一意思的碎片，拆开承担多个独立任务的长段，让解释、证据与推论连起来。
- **防御性写作**——直接展开有依据的观点，清理无关辩解和重复免责，保留影响结论的真实限制。
- **自然表达**——把抽象堆叠还原成具体关系，清理套路化句式、重复总结和装饰性格式，保留适合文体的语气。

## 开始使用

先克隆仓库，或在 [GitHub 仓库页面](https://github.com/kjsmmm/Consistent-Writing) 选择 **Code → Download ZIP** 并解压：

```sh
git clone https://github.com/kjsmmm/Consistent-Writing.git
```

选择目标语言，将对应的完整技能文件夹复制到所用工具的技能目录，按该工具的说明加载技能。可以只安装一种语言，也可以同时安装两种。每份技能的全部规则都在一个 `SKILL.md` 中，无需脚本、依赖包或外部服务。

| 写作语言 | 技能文件夹 | 调用名 |
| --- | --- | --- |
| 中文 | [clear-chinese-writing](./clear-chinese-writing/) | `$clear-chinese-writing` |
| English | [clear-english-writing](./clear-english-writing/) | `$clear-english-writing` |

Consistent Writing 是项目名称；技能目录与调用名保留为上表中的名称。安装后的结构应是 `技能目录/clear-chinese-writing/SKILL.md` 或 `技能目录/clear-english-writing/SKILL.md`。

在支持 `$技能名` 调用方式的工具中，可以直接使用下面的请求。其他工具可按其技能调用方式选择对应技能。

**从零起草**

```text
用 $clear-chinese-writing 根据下面的材料起草一份项目方案。
读者是项目负责人，重点说明为什么做、怎么做、如何判断是否有效。
```

**只改当前一段**

```text
用 $clear-chinese-writing 修改下面这一段。
结合前面已经确定的主旨和术语，保留这一段的关键理由。
```

**压缩成稿**

```text
用 $clear-chinese-writing 把这份说明压缩到约 800 字。
保留核心观点、主要依据和适用条件。
```

**Revise an English passage**

```text
Use $clear-english-writing to revise the following section.
Keep it aligned with the document's purpose and established terminology.
Preserve the reasons and qualifications that support its claims.
```

## 只有一段，也可以开始

已有对话或正文足以确定主旨和术语时，技能要求直接利用这些信息。只有孤立片段，且缺失信息会影响修改方向时，AI 应先问清这段的用途、想表达的观点或术语含义。含义完整的段落和单纯的语法修改可以直接处理。

上下文由当前对话和正文提供。技能通过这些材料检查一致性，使用过程中无需另建主旨记录、术语库或修改日志。

## 看改稿时，检查这三件事

1. **意思还对吗？** 这段是否继续服务于原来的主旨，主张有没有被悄悄放大？
2. **概念还清楚吗？** 同一名称是否仍指同一件事，新名称是否解释到位？
3. **该留下的还在吗？** 理由、证据、条件和具体收益，是否还能在改稿中找到？

这些检查也写在技能内部。它们是生成与修订的判断规则，实际效果仍取决于模型和可用上下文。

## 反馈与改进

如果改稿出现跑题、术语漂移或过度删减，欢迎[提交 Issue](https://github.com/kjsmmm/Consistent-Writing/issues)，附上经过脱敏的原文片段、修改请求、实际输出，以及你希望保留的意思。具体的修改前后对照，有助于判断问题出在主旨理解、概念辨认还是信息取舍。也欢迎提交 Pull Request；修改共同规则时，请同步检查中英文两份技能是否表达一致。
